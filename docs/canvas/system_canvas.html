01Overview

AranMed runs as seven containers behind one gateway, on a single 11 GB GPU. Two product surfaces share the backend: a dictation pipeline that turns speech into a template-structured radiology report, and an agentic clinical assistant that builds EHR records, tracks medication schedules, and answers grounded knowledge questions.

service

gateway

nginx. Load-balances replicas over Docker DNS, rate-limits the expensive AI endpoints, optionally terminates TLS. Publishes port 8090.

service

backend

FastAPI. Dictation and report routes, the tool-calling agent, model registry, EHR store, auth.

service

frontend

Next.js. Role-scoped views; a custom server proxies /api to the backend.

service · gpu

vllm

Serves the core LLM over an OpenAI-compatible API. Qwen3.5-4B at 4-bit, with tool-call and reasoning parsers enabled.

service · gpu

triton

Whisper large-v3 out of process, on CUDA. The default and only ASR path, so transcription never occupies an API worker.

service

medrag

MedicalRAG engine — ingestion, retrieval, self-critique, grounded answers. Generates through the same vLLM.

service

qdrant

Vector store for the embedded medical corpus.

optional

postgres

Opt-in storage backend when SQLite's single writer becomes the ceiling. Same schema, same SQL, no code change.

No Ollama in the inference path. The registry still carries an Ollama slot for deployments that want one, but this deployment is OLLAMA_ENABLED=false throughout: the core LLM, the agent, and MedicalRAG's answer generation all resolve to the same in-network vLLM. Inference is vLLM and Triton, nothing else.

02Architecture

Every host and port below resolves from an environment variable at runtime. No address in this diagram is hardcoded in application code — an enforced project rule, not an aspiration (§11).

03Request flows

Three paths through the backend. Which one runs is decided by what the request carries and, for text, by what the model decides it needs — not by a mode flag the caller sets.

Flow B used to be a hard branch, and that was a defect. Every text-only turn short-circuited to MedicalRAG and returned, which made all 17 tools unreachable unless the caller attached audio or an image. "List the EHR records" came back as a knowledge non-answer, because no tool could ever run. Retrieval is now a tool like any other and the model routes for itself; the old behaviour survives as CHAT_TEXT_ROUTE=medrag for a knowledge-only install.

04Agent orchestration

A registry pattern, not an if/elif chain: a @tool decorator registers each Tool subclass into one dict, and the agent dispatches generically. Seventeen tools are registered.

Observed routing on the deployed stack, one session, three consecutive turns — the model picks correctly without any router heuristic:

"List the EHR records you have access to."          → list_ehr
"What report templates exist for thyroid imaging?"  → list_templates
"Ultrasound features of acute cholecystitis?"        → medical_knowledge

Memory

Last N turns verbatim; older turns condensed into a summary by the core LLM. A per-conversation asyncio.Lock guards that read-modify-write. The in-process dict is bounded by idle-TTL and max-session eviction, while the durable copy lives in agent_sessions and is purged on a configurable interval.

EHR safety

LLM-authored EHR JSON is validated and type-coerced by a pydantic schema before it is persisted or reaches dosing math. Patient identity resolves by explicit id, then MRN, and only then mints a fresh id with a numeric suffix — never by silently reusing a name-slug.

07Deployment

The stack is deployed and running on a dedicated GPU server. Everything below is measured on that machine, not estimated.

hardware

RTX 2080 Ti

11 GB, Turing/sm75. 32 cores, 88 GB RAM, Ubuntu 22.04. No bfloat16, no FlashAttention-2, no CUDA forward compatibility.

core llm

Qwen3.5-4B

4-bit bitsandbytes on vLLM. max_model_len 6144, max_num_seqs 8, thinking disabled for structured output.

asr

Whisper large-v3

Served by Triton on CUDA, task=transcribe. Roughly 7 s for a 45-second dictation.

Do not run the card to its limit. An earlier configuration at VLLM_GPU_MEM_UTIL=0.68 with Whisper also on GPU reached roughly 10.8 of 11.26 GB and hung the entire host — no SSH, no ICMP, requiring a power cycle and ultimately a reimage. Leave about 2 GB free.
VLLM_GPU_MEM_UTIL is a startup free-memory check, not an allocation. It tells vLLM how much of the card it may assume is available when sizing the KV cache. Raising it reserves nothing; lowering it shrinks no weights. Reasoning about it as a memory cap leads to exactly the wrong conclusion about what fits.

SettingWhy it is not a default
VLLM_MAX_NUM_SEQSQwen3.5 is hybrid Mamba/attention and needs one Mamba cache block per decode sequence. vLLM's default of 256 refuses to start: "max_num_seqs (256) exceeds available Mamba cache blocks (46)".
VLLM_MAX_MODEL_LENMust exceed the report prompt (naming rules + template + transcript) plus output. Too small returns 400 on reports while plain chat still works — which reads like a prompt bug, not a sizing one.
VLLM_TOOL_CALL_PARSERThe agent always sends tools; without --enable-auto-tool-choice and a family-correct parser, vLLM answers 400.
VLLM_REASONING_PARSERWithout it, chain-of-thought lands in content and the report opens "Thinking Process: 1. Analyse the request…".
VLLM_EXTRA_BODYA reasoning model filling a template spends the whole budget thinking and returns an empty report with no error.
WHISPER_TASKThe accuracy-critical one. See below.
VLLM_QUANTIZATIONQwen3.5-4B is vision-language and its fp16 checkpoint is 9.32 GB — it OOMs even with the whole card. Leave the value empty for unquantized; a literal none is rejected.
WHISPER_TASK=transcribe is not optional for clinical use. Left unset, the task derives from WHISPER_OUTPUT_ENGLISH=1 and becomes translate — a paraphrasing decode. Measured on the same audio file, byte-for-byte:

The damage compounds downstream: the mangled transcript also drove template auto-selection to abdominopelvic_for_male instead of hepatobiliary. This setting is necessary but not sufficient — the English is produced by a second, LLM translation stage that fabricates independently of it (§14).

Entry points

Three parallel entry points, all idempotent: deploy.sh (Linux/macOS/WSL), deploy.ps1 (Windows), and make deploy. Each checks Docker and GPU availability, bootstraps .env, warns on duplicate keys and an empty corpus mount, builds every image, prefetches models, brings the stack up, restarts the gateway so nginx re-resolves upstream IPs, then polls until healthy.

--force-recreate does not rebuild the image. Backend sources are COPYed in, not mounted, so editing a file on the server and recreating the container silently reruns the old code — the change appears to have no effect, which sends you hunting a second bug that does not exist. This cost more debugging time than any other single fact about the deployment. After touching anything under backend/: docker compose build backend && docker compose up -d backend.

Dictation, end to end

Open defect — read before trusting any transcript below. /api/transcribe is two stages: Whisper produces Persian, then a 4B model translates it to English. The translation stage fabricates. On a 41.9 s sample it invented the anatomy (a portal vein never mentioned), invented findings ("no thrombus", "no focal lesions"), invented a measurement, and inverted a negation — producing three mutually incompatible readings from identical input. The English below is fluent and plausible; it has not been checked against the raw Persian. See docs/core/ASR_TRANSLATION_CONFABULATION.md.

The reference sample, as returned by the endpoint — presented as observed output, not as verified truth:

For patient Sary Rahimi, a hepatobiliary ultrasound was performed. The liver is normal in size with normal echogenicity; the gallbladder is normal, and the proximal, middle, and distal portions of the biliary tree are normal. The pancreas is normal. The spleen is normal. No cholelithiasis is noted.

The same audio through /api/dictate selects hepatobiliary and returns a filled report with one line per finding — no * alternatives, no unfilled placeholders:

Hepatobiliary Sonography:
Liver is normal in size and shows normal parenchymal echogenicity and no sign
of space occupying lesion or bile ducts dilatation is noted.
Gall bladder is well distended with no stone or wall thickening.
No pericholecystic fluid is noted.

Templates carry alternatives, and the model has to choose. Each finding appears as a default line followed by *-prefixed variants — mutually exclusive phrasings, not separate findings. Emitting all of them produces a 1507-character template dump of contradictory statements rather than a report; choosing one per group produces the 484 characters above from the same dictation. The prompt states the rule, and a deterministic pass strips any residue that survives it.

09Security

SQL injection — structurally prevented

Every database call uses parameter binding. No query is built by interpolation, formatting, or f-string, so attacker-controlled text is never parsed as SQL. A repo-wide search for interpolated queries returns nothing, and that search is the documented regression check. An escaping helper was deliberately not added — it would imply interpolation is acceptable somewhere, which is the weaker guarantee.

The probe confirms this behaviourally rather than by inspection: ten auth-bypass payloads, a time-based blind probe, and a DROP TABLE attempt all fail, and the schema survives. The throttle table is incidental proof — it stores '; drop table users; -- as a literal key, inert.

The audit trail carries no PHI

resource is an identifier like patient:ali-reza; detail holds field names, counts and reasons. Never diagnoses, names, or note text — a trail that leaks PHI widens the breach surface it exists to narrow. Reading it requires audit.read and is itself recorded.

Two checks, not one

RBAC decides whether a caller may touch EHR at all; owner_user_id decides which records they see. They are independent and both must pass, so a role grant can never widen access across owners.

Two settings decide whether security holds at scale. ASR_AGENT_SECRET must be set before running more than one backend replica — otherwise each worker signs tokens with its own random key and sessions break across replicas. And the throttle backend must stay shared: per-process counters hand an attacker N× the attempt budget at N replicas, because the gateway spreads their guesses across all of them.

10Scaling

The topology was always horizontally scalable — --scale backend=4 --scale medrag=3, nginx balancing over Docker DNS. What changed is what happens to state when you actually do it, and the load runs above show what happens to latency.

Before

Conversation memory lived in one worker's process dict, so a session's history was wherever nginx happened to route — often nowhere. Login throttle counters were per-process, multiplying the attacker's budget. A hung LLM or tool call held a worker slot with no bound. SQLite's default journal blocked readers for the whole of every write.

After

Memory is durable in shared SQLite and rehydrates on whichever replica gets the next request. Throttle counters are shared, so the lockout is global. Every LLM and tool call is timeout-bounded, so a stuck call frees its worker. WAL lets readers proceed during writes, and busy_timeout makes a concurrent writer wait rather than fail.

On this hardware the bottleneck is the GPU, not the API tier. 100 concurrent agent turns all completed, but p50 was 91 s because eight sequences decode at a time. Adding backend replicas will not move that number — raising VLLM_MAX_NUM_SEQS (with VLLM_GPU_MEM_UTIL to back it) or adding GPUs will. Scale the tier that is actually saturated.

Checklist before --scale backend=N

  1. Set ASR_AGENT_SECRET — otherwise tokens do not validate across replicas.
  2. Leave the throttle backend shared (auto or redis), never memory.
  3. Keep DB_JOURNAL_MODE=WAL — replicas share one database file. Past the point where a single writer is the bottleneck, set DATABASE_URL and run PostgreSQL instead; no application code changes.
  4. Memory needs nothing extra; it is already durable and rehydrates on any replica.

11Configuration & the no-hardcoding rule

Every host, port, path, model id, limit, and timeout resolves from configuration. Three surfaces, chosen by what the value tunes:

.env

Service discovery, credentials, TLS material, model topology, database pragmas, throttle policy. Anything an operator changes per deployment or must never commit.

models.yaml → runtime.*

Agent loop bounds, per-call timeouts, generation budgets, memory window and eviction, purge interval. These live beside the model registry they tune.

backend/data/

Clinical content: report templates, hospital naming rules, RBAC policy, terminology bindings, report clean-up patterns. Editable files with in-code fallbacks.

The most expensive lesson was not a code defect. docker compose up --force-recreate does not rebuild an image, so an edited backend file kept running the old code — and every fix looked like it had failed. Time lost to that single misunderstanding exceeded any individual bug on this page.

14Known limits

One open defect, then the set of things that are genuinely someone else's job, deliberate design decisions, or operational rather than technical:

  • OPEN · CLINICAL SAFETY — the English transcript is a confabulation. Whisper transcribes Persian faithfully; a 4B model then translates it, and that stage invents anatomy, findings and measurements, and inverts negations. Three runs of one input gave three incompatible clinical readings. It is invisible from the outside because the output is fluent and well-formed — it reads like a better transcript than the truth. Full evidence and fix directions in docs/core/ASR_TRANSLATION_CONFABULATION.md; scripts/asr_translate_probe.py is the regression check.
  • The knowledge corpus is not on this server. MedicalRAG, Qdrant and the answer LLM are all healthy, but the store holds 0 chunks until the ~19 GB corpus is transferred. Knowledge answers currently fall back to the model's own knowledge, which is exactly what a grounded system is supposed to avoid — so knowledge quality is unverified here, not verified-good.
  • This deployment serves plain HTTP. Credentials and clinical text cross the network in the clear. TLS is implemented and one flag away; it is off, and that is a deployment decision to revisit before real patient data.
  • The template-mismatch detector is over-eager. It can append a trailing "NOTE: Dictation appears to describe …" even when the selected template does match the dictation. Cosmetic, but it lands in the report body where a clinician will read it.
  • PHI key custody is operational, not automatable. The system warns at startup, proves every key referenced by stored rows is loaded, and can decrypt-check every record before you trust a restore — but it cannot verify that a backup exists somewhere safe. Losing the key loses the data. That is the property that makes the encryption worth having.
  • No MLLP listener or DICOM C-STORE SCP. Both are network listeners with their own lifecycle, ports and failure modes; they belong in their own process, not inside the API. The parsing and generation they would carry is done.
  • FHIR is a read-only projection — deliberately. Becoming a FHIR-native store means FHIR resources as the internal model, which is a different system, not a bigger version of this one.
  • SNOMED CT cannot be vendored. It is licensed. The bundled file is a curated starter set and a terminology server handles the rest; with none configured, unbound terms stay text-only rather than being guessed at.
  • The gateway does not verify the upstream certificate under internal TLS. That still defeats passive sniffing; authenticated upstreams need proxy_ssl_verify on and a trusted CA, which is a certificate-management decision, not a code one.
On "no further enhancement needed". Every gap these reviews found is closed and verified against the running stack. But a clinical system earns its status continuously, not once: models drift, dependencies get CVEs, corpora go stale, and regulation moves. The honest claim is that there is no known outstanding defect and no capability claimed that is not implemented — not that the work is permanently finished.
